# 代码改动

目标：每次改动都能**编译通过 + 能跑 + 有证据**，且改动范围可解释。

## 先谈契约（不要跳过）

动手前明确三件事，缺哪个就问：

1. **改什么**：目标行为，不是"优化一下"，而是"按 F 键切换后能立刻看到 A/B 对比"。
2. **怎么算改完**：可观察的验收条件（画面 / 日志 / 数值 / 帧时间）。
3. **不碰什么**：明确排除的范围（例如"别动 VRPG，只改 LPV"）。

用户说不清验收条件时，给他两个低成本选项让他挑，不要自己猜。

## 流程

1. **读**：目标文件全文 + 调用方 + `AGENTS.md` 相关段 + 模块 `README.md`。
   顺手确认这个文件是 UTF-8 还是 GBK（见 AGENTS.md「编码坑」）。
2. **计划**：≤5 步，每步写清"改完怎么验证"。大改动先把计划给用户看一眼。
3. **改**：最小编辑。**不要整文件重写 GBK 文件**，不要顺手重排缩进。
4. **构建**：`cmake --build build --config Release --target FzbRenderer_nvvk`。
   失败先读第一条错误，不要连续盲改。
5. **验证**：按 AGENTS.md「运行与验证」跑一次，记录日志关键行与截图。
6. **报告**：改了什么、为什么、怎么验证的、还有什么没验证。

## 反向约束

- 改 shader 后画面没变化 → 先删同名 `.spv` 缓存，再判断是不是代码没生效。
- 卡住超过两轮 → 停止盲改，降级成"只读分析 + 给方案"，把选择权交回用户。
- 不新建 `.bak` / `.zip` / `_copy` 快照；回退用 git。没有提交基线时先提醒用户。

## 输出模板

```
改动：src/renderer/LPV/LPV.cpp:210-238（给间接光 pass 补 memory barrier）
理由：上一 pass 写入的 SSBO 在 compute 读取前缺少 barrier
验证：Release 构建通过；跑 veach-ajar-2 无 validation 报错；对比 01/02 帧
遗留：只验证了单帧，多帧累积未验证
```
